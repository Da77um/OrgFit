# OrgFit proposed relational schema — Phase 01

2026-09-08 · DESIGN DRAFT, NOT AN EXECUTABLE MIGRATION

Phase 04 implementation note: migrations 005/006 retain instrument relational topology and scope/version FKs while grouping node-local translations/declarative settings in strict JSONB payloads. See [instruments.md](instruments.md) and D-042 for the actual contract; later entities below remain proposed.

This is the equivalent schema draft permitted by Phase 01. It specifies PostgreSQL tables, types and constraints without installing a database or writing application behavior. Read with [data-model.md](data-model.md), [state-machines.md](state-machines.md), [api-contracts.md](api-contracts.md) and [privacy-protocol.md](privacy-protocol.md). Later migrations must implement the constraints and named guards below and test them; this document is not SQL execution evidence.

## 1. Exact notation and inherited columns

All listed fields are NOT NULL unless suffixed `?`. `uuid` is random UUIDv4 generated by a CSPRNG, never ordered by acceptance time. `text`, `boolean`, `integer`, `bigint`, `bytea`, `jsonb`, `numeric`, `date` and `timestamptz` are PostgreSQL types. `enum(A,B)` means text plus a database CHECK restricting those exact values. `J(name)` means jsonb with the closed, versioned shape in section 8; reject unknown keys in service validation. A database CHECK verifies object/array kind and byte size; named publish/transition guards verify referenced keys and semantic constraints. No JSON is executable code. Numeric fields reject NaN and infinities. Text limits in API contracts also apply on persistence. Empty strings are not valid required titles/codes.

Every table declares a base below; base columns are real columns in the future physical table, not implicit relationships:

| Base | Columns and keys |
|---|---|
| M | `id uuid PK; created_at timestamptz; updated_at timestamptz; revision bigint DEFAULT 1 CHECK >0; created_by uuid?; updated_by uuid?`. Actors FK access.staff_user(id), delete RESTRICT. Actor null only for system creation. |
| O | M plus `organization_id uuid FK core.organization(id)` and UNIQUE(organization_id,id). |
| I | `id uuid PK; organization_id uuid FK core.organization(id)` and UNIQUE(organization_id,id). No generic audit/time/revision columns. Used for completion-sensitive rows. |
| V | M plus `scope_id uuid FK instrument.instrument_scope(id); organization_id uuid? FK core.organization(id)` and UNIQUE(scope_id,id). Scope consistency guard requires child organization_id IS NOT DISTINCT FROM scope's organization_id. Organization scope therefore always has non-null organization_id; only global scope may be null. |
| A | `id uuid PK; organization_id uuid; campaign_id uuid` and UNIQUE(organization_id,campaign_id,id). No cross-database FK, timestamps, revision, actor, transport or identity metadata. |

PK overrides are explicit. `FK org: x -> table` means `(organization_id,x) REFERENCES table(organization_id,id) ON DELETE RESTRICT`. `FK campaign: x -> table` means `(organization_id,campaign_id,x) REFERENCES table(organization_id,campaign_id,id) ON DELETE RESTRICT`. `FK scope: x -> table` means `(scope_id,x) REFERENCES table(scope_id,id) ON DELETE RESTRICT`. All parent key tuples referenced below must have corresponding UNIQUE constraints in addition to the stated PK. Every FK column tuple gets a B-tree index unless a PK/UNIQUE index already covers its leading columns. This indexing rule applies to every row below, including actor and optional FKs. Additional workload indexes are listed explicitly.

Default deletion is RESTRICT, never automatic cascade across a security boundary. Lifecycle/retention codes: `R` archive/config/history retention (approved business schedule); `D` unpublished-only explicit child-first deletion; `T` temporary purge under section 9; `AN` whole-campaign anonymous purge only; `S` immutable safe snapshots; `AU` sanitized audit; `SEC` ephemeral security state. Publication/launch guards serialize mutations and enforce immutability of all children; a table CHECK alone cannot inspect another row. [PostgreSQL constraints](https://www.postgresql.org/docs/18/ddl-constraints.html) is the implementation reference.

## 3. Core database: immutable instruments

`org` in uniqueness notation means organization_id. Global instrument scope has exactly one row with null organization_id: UNIQUE NULLS NOT DISTINCT(organization_id). No sentinel/fake organization is used. Every V child carries scope_id and matching nullable organization_id; immutable scope prevents moving an instrument between organizations. An org-owned campaign may pin a GLOBAL instrument or one owned by that same organization, enforced by launch/create guard. No campaign can pin another organization's instrument.

Draft deletion explicitly deletes children in dependency order; published lineage cannot be deleted through CRUD.

### 8.1 Physical-schema clarifications from design review

In key tuples, `org`, `scope`, `version`, `campaign`, `snapshot`, `group`, `question`, `section`, `set`, `instance`, `series`, `round`, `participant`, `invitation`, `batch`, `report` and `comparison` abbreviate their corresponding `_id` fields, except publication aggregate/recommendation `group` means `group_key`. Targets `version`, `round`, `group`, `response`, `snapshot` and `instance` refer to questionnaire_version, assessment_round, report_group/anonymous_group (by database), anonymous_response, result_snapshot and recommendation_instance. Composite referenced tuples receive UNIQUE constraints as required by §1; no cross-database reference is implied by a logical campaign ID.

Additional physical columns/receipt table required by the contracts:

- `core.assessment_round.archived_from enum(PUBLISHED,INSUFFICIENT_DATA,CANCELLED)?`: non-null iff state ARCHIVED, preserves terminal outcome.
- `publication.report_artifact.generation_number integer DEFAULT 1 CHECK >0`: include in generation_key. First request allocates generation 1; after expiration/revocation, a newly authorized request may allocate next generation under the source lock. The same idempotency key always returns its existing receipt; active identical generation deduplicates. A revoked source cannot be regenerated until an eligible approved source exists.
- `ops.private_export.encrypted_payload bytea?; export_key_reference text?`: LINKS kind requires these after generation until expiry (payload up to 16 MiB); other kinds keep both null. Token generation/digest updates and encrypted export payload persist in one core transaction. Blob is gateway/issuer-only, not ordinary staff SELECT; export view excludes it. An upload worker copies ciphertext, never recreates tokens. Purge blob and temporary export key within 24h. See privacy protocol §2.1.
- `access.global_mutation` (no O base): `id uuid PK; staff_user_id uuid FK staff_user; operation text; idempotency_key uuid; request_digest bytea; resource_id uuid?; response_status integer; expires_at timestamptz`; UNIQUE(staff_user_id,operation,idempotency_key), digest32 bytes, index(expires_at), retention T/24h. No org-owned operation may use this global receipt to bypass organization scoping.

Decoded draft plaintext and canonical final-answer set are each capped at 1 MiB. Sealed envelope<=2 MiB and HTTP JSON including base64<=2 MiB; client/server reject before persistence if encoding expansion exceeds that ceiling. Publish validation computes attainable UTF-8 maximum under configured string/item limits and prevents mandatory content exceeding the answer cap. A smaller actual bound may be required for optional content; respondent validation must explain it before submission. No silent truncation.

## 9. Retention mapping

R: archive normally, no CRUD deletion of published/history dependencies; owner business retention still P-004. D: only unpublished unreachable drafts deleted child-first. T: encrypted imports expire after 24h by default; staff idempotency receipts 24h; link exports <=24h; report files default 7d (regeneration from snapshots allowed); draft idle TTL 30d with acknowledged-write renewal capped at closure+7d; accepted drafts deleted immediately; insufficient/cancelled intake <=30d from terminal transition. These added TTLs are nonproduction defaults pending P-004. Processed intake purged immediately after verified output and keys destroyed under privacy protocol. AN: 12 months from campaign closure then whole campaign purge. AU: 12 months. SEC: expire/revoke plus short cleanup, never historical analytics. Backups 35d, deletion ledger retained at least until every containing backup and key recovery window has expired; longer business retention decided by owner. No secret or answer resurrected merely because backup restore succeeded.
